# login-jwt

## Intenção

1. Quem abre o dashboard sem estar logado vê uma tela de login com a identidade da GeniAI (logo, tema escuro, gradiente), e não o pop-up nativo do navegador.
2. O login gera um JWT (HS256, 7 dias) guardado num cookie `httpOnly`. Enquanto ele vale, a pessoa entra direto. Quando vence, volta ao login, e o navegador preenche usuário e senha.
3. O botão "Sair" encerra a sessão antes do prazo.
4. O webhook da Z-API segue fora do login.

## Critério de aceite

```bash
cd web && npm test && npm run lint && npx tsc --noEmit && npm run build   # sessao.test: token válido, adulterado, vencido, alg none, credenciais, open redirect
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' localhost:3000/          # 307 http://localhost:3000/login?de=%2F
curl -s -o /dev/null -w '%{http_code}\n' localhost:3000/login                     # 200
curl -s -o /dev/null -w '%{http_code}\n' -X POST localhost:3000/api/webhook/x     # 404
```

No navegador (`playwright-cli`), testar três coisas:

- senha errada mostra erro;
- login certo abre `/`, e o reload continua logado;
- "Sair" volta ao login.

## Fora de escopo

- Vários usuários, cadastro, recuperação de senha, papéis.
- Rate limit de tentativas.
- Refresh token e revogação individual. Trocar `AUTH_SECRET` derruba todas as sessões.
